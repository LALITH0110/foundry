# Evidence

Only sanitized evidence belongs here. A genuine discovery run stores its model decisions, UI observations, executed actions, and compiled artifact provenance under a run ID. Replay runs explicitly record `modelRequests: 0`.

Each committed discovered artifact is the direct output of the discovery run recorded here. `npm run check:evidence` verifies that every artifact's `provenance.discoveryRunId` and model match its run manifest, so a stale or hand-edited artifact fails the check.

The bootstrap contracts in `capabilities/*.example.json` are engineer-authored and are not represented as discovery evidence. Development runs live under `evidence/runtime/` and remain ignored. The selected runs under `evidence/reviewed/` were copied with `npm run curate:evidence` and scanned with `npm run check:evidence`.

Scenario evidence is generated by the deterministic test harness. Handoff cases use scripted operator callbacks so CI can verify ownership transfer, recorded human actions, and resume predicates; `npm run demo:handoff` is the separate manual path.

The two approval scenarios are the one case where the replayed artifact is not the committed one. The stop-payment workflow stops before the financial commit and so contains no irreversible step; to exercise the approval gate the test promotes the `Continue to review` step's effect to `irreversible` on an in-memory copy of the discovered artifact. The gating behavior and the recorded evidence are genuine, the irreversible step is synthetic, and nothing under `capabilities/` is modified.

## Where to look first

| Path                                | What it proves                                                                                                 |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `discovery/`                        | Genuine qwen3:4b run that discovered the stop-payment route against the live UI                                  |
| `replay/`                           | The same artifact replayed with different inputs at `modelRequests: 0`                                           |
| `lookup/discovery/`                 | A second qwen3:4b run against a contract with **no pre-authored route**; every executed step came from the model |
| `lookup/replay/`                    | The draft lookup artifact replayed for a different member, extracting a name no input supplied                   |
| `policy/blocked-submit.json`        | The final submit action refused by the policy gate                                                               |

## Scenario index

Each directory is one deterministic run. `manifest.json` identifies it; `events.jsonl` is the redacted step log.

| Scenario                          | What it proves                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------------ |
| `member-not-found`                | An unknown member returns `MEMBER_NOT_FOUND` as a typed business outcome, not a crash        |
| `account-not-found`               | A missing account is classified from a screen-confirmed precondition, not an ambiguous miss  |
| `restricted`                      | A restricted account returns `ACTION_NOT_PERMITTED` to the caller                            |
| `app-error`                       | A host error stops as an `APP_ERROR` failure with a sanitized snapshot and masked screenshot |
| `timeout`                         | An unmet postcondition expires as `TIMEOUT` rather than proceeding blindly                   |
| `known-interstitial`              | One contract-defined recovery action dismisses a known interstitial and replay continues     |
| `recovery-escalation`             | A recovery that fails once escalates to `UNEXPECTED_STATE` instead of retrying forever       |
| `session-expired`                 | Session expiry transfers the live session to a human and resumes on a validated checkpoint   |
| `session-expired-before-account`  | Expiry before account selection stays `SESSION_EXPIRED`, never mislabelled `ACCOUNT_NOT_FOUND` |
| `unexpected-state`                | A human repairs an unknown state in the same session and the engine validates the resume     |
| `approval-pending`                | An irreversible step left unapproved stops as `APPROVAL_REQUIRED` and never executes         |
| `approval-success`                | The same step runs only after an explicit operator approval, under a new ownership epoch     |
| `action-budget`                   | A one-action session budget blocks the second action                                         |
| `action-budget-after-handoff`     | The budget is monotonic: a human handoff does not reset it                                   |
| `corrupt-review-reason`           | A corrupted final field fails verification, so a wrong screen cannot be reported as success  |
| `lookup-draft-refused`            | Unattended replay of a `draft` capability is refused before any UI action is taken           |
| `lookup-member-not-found`         | The draft lookup capability still classifies declared business outcomes when run attended    |

Replay manifests record `lifecycle` and `attended`. A run of a `draft` capability is only possible with `attended: true`, so the evidence shows on its face how a draft was allowed to execute; `lookup-draft-refused` is the same capability with `attended: false`.

Success and intervention snapshots contain semantic control inventories rather than unrestricted page text. Failure screenshots mask form fields and table values. Inputs, seeded names, cookies, storage, raw prompts, traces, video, HAR files, and unmasked screenshots are excluded.
